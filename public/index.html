Building Backend Systems in Go

Go makes the first server feel solved. Then a retry, a collision, a slow database, or a deploy at the wrong moment arrives. This book is about being prepared. Decide how it fails when you decide how it works.

The running project

Forge, a task API, begins with three endpoints and grows only when the system needs the next idea.

Part I is the thinking: what a backend is, how a request moves, what to decide before code, and the first service that makes those decisions visible.

Five principles

Make it workA running system teaches more than a perfect design on paper.
Make boundaries explicitKnow where handler, service, database, and network end.
Make failure ordinaryErrors, timeouts, and partial failure are normal inputs.
Make concurrency deliberateEvery goroutine has an owner, a lifetime, and a reason.
Make production observableIf you cannot see it, you do not control it.

Questions readers ask

What is Defer Nothing?

A practical book about designing, building, testing, deploying, and operating production backend services in Go. The title is a habit: decide how it fails when you decide how it works.

Who is it for?

You should be comfortable with variables, functions, and reading someone else's code. Prior Go is not required. Junior and mid-level backend engineers get a path from first service to production. Experienced developers can use it as a refresher and a checklist.

What can I read now?

The introduction and Part I, chapters 1 to 4. Later parts, from HTTP itself through persistence, rules, concurrency, and production, will be added here as they are written.
